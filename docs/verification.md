## Условия и границы проверки

- Python локально: 3.13.7; Docker/CI целятся в Python 3.12. Зависимости закреплены lock-файлами.
- Локальные HTTP и Redis-integration проверки использовали **TCP Redis emulator (fakeredis с Lua)**. Production использует Redis из Docker, а CI настроен на настоящий Redis. Эмулятор не входит в runtime, lock-файлы или Docker-образы проекта.
- Telegram API в unit/FSM-тестах заменён тестовым transport; настоящий BOT_TOKEN не предоставлен. Реальная отправка пользователю не проверена.
- Автоматический Playwright runner локально не стартовал из-за `spawn EPERM` в Windows sandbox. Вместо него выполнена проверка UI через встроенный браузер. Playwright E2E-сценарий сохранён и подключён к CI, но **прохождение CI не заявляется**: workflow здесь не запускался.
- Docker Engine отсутствует в локальной среде. Контейнерная сборка и полный `docker compose up` здесь **не выполнялись**. Проверены конфигурационные файлы и приложение вне Docker; перед production запуском требуется проверка контейнеров на целевом Linux-хосте.
- TLS-домен, аварийный номер, доставка Telegram и восстановление production backup требуют приёмки в инфраструктуре заказчика.
- Тестовые записи хранились в отдельной БД в `work/`; база, фотографии, тестовые сессии и секреты не включены в архив. В production инициализируются только пустые таблицы и системные настройки.

## Исправления по результатам проверки

- Разные имена enum-check constraints для old_status и new_status: SQLite позволяла дубликат, PostgreSQL отклонил миграцию.
- Последовательность SSE событий сериализуется PostgreSQL advisory lock до commit, чтобы поздний commit не терялся за курсором.
- Отключено сжатие SSE; добавлен `no-transform`.
- Ограничено пространство позиционирования скрытых заголовков таблицы: мобильная страница больше не получает горизонтальный скролл из-за accessibility label.
- Политика Referrer для тайлов соответствует [требованиям OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/); передаётся origin, без URL заявки.

## Приёмка на сервере

1. Выполнить инструкции README: environment → TLS → build → migrate → SUPER_ADMIN → compose up.
2. Через реальный Telegram выполнить каждый сценарий, отмену/назад и повторное нажатие подтверждения.
3. Сменить статус, проверить фактическую доставку, внутренний/публичный комментарий и очередь при блокировке бота пользователем.
4. Войти OPERATOR и убедиться, что чужие заявки, фото и отчёты недоступны.
5. Проверить SSE при reconnect, restart backend и одновременной работе сотрудников.
6. Проверить восстановление БД и фотографий на отдельном хосте, затем утвердить ввод в эксплуатацию.
