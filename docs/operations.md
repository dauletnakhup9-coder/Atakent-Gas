# Эксплуатация

## Контроль работоспособности

- `/api/health/live`: процесс API жив.
- `/api/health/ready`: доступны БД, Redis, строка настроек после миграции. Нет сведений о секретах.
- `docker compose ps`: состояния контейнеров и healthchecks.
- `docker compose logs --tail=100 bot worker backend`: ошибки обработки без токенов и текстов заявок в прикладных логах.
- SUPER_ADMIN → «Баптаулар» → очередь уведомлений: pending / failed; кнопка повторной доставки после исправления причины.
- Настройте внешнюю проверку HTTPS, сроков TLS, свободного места, резервных копий и роста pending/dead-letter. `health/ready` не проверяет отправку реальному получателю Telegram; такую проверку делайте на согласованном тестовом аккаунте.

Worker выполняет до 12 попыток с backoff; 403 (бот заблокирован) и 400 уходят в failed. Telegram 429 учитывает retry_after. Отказ Telegram не откатывает статус заявки. Все публичные сообщения попадают в outbox в той же транзакции, что и изменение.

FSM хранится в Redis 24 часа, per-user event isolation предотвращает гонки двойных нажатий. Предварительные фото без заявки удаляются worker через 24 часа. При остановленном worker очистка и доставка возобновятся после старта. Не удаляйте Redis volume при штатном обновлении.

## Резервные копии

Сохраняйте PostgreSQL и uploads **как согласованный комплект**. Для простого single-host snapshot временно остановите все записи:

```sh
docker compose stop nginx bot worker backend
mkdir -p backups
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/utility.dump'
docker compose cp postgres:/tmp/utility.dump ./backups/utility.dump
docker compose run --rm --no-deps --user root -v "$(pwd)/backups:/backup" backend tar -czf /backup/uploads.tar.gz -C /data/uploads .
docker compose start backend worker bot nginx
```

Команды Unix shell. В PowerShell используйте абсолютный путь вместо `$(pwd)`. Защитите и шифруйте backup, храните копию вне хоста; ограничьте доступ, определите retention с владельцем данных. Не коммитьте backup. Для более короткого RPO настройте WAL archiving/PITR и snapshots общего object storage.

## Восстановление

Проверяйте восстановление сначала на отдельном сервере и пустых volumes. Подготовьте совместимую версию PostgreSQL, перенесите dump, выполните `pg_restore` в пустую БД, восстановите uploads в приватный volume с владельцем UID 10001, примените необходимые миграции. Проверьте фото, количество заявок и историю перед включением bot/worker. Не направляйте тестовое восстановление на production BOT_TOKEN: outbox из backup может повторно отправить старые уведомления.

## Обновление

1. Прочитайте миграции и изменения зависимостей, выполните CI.
2. Создайте backup. Сохраните предыдущие образы и commit.
3. Выполните `docker compose build`, затем в окне обслуживания `docker compose run --rm migrate`.
4. Выполните `docker compose up -d` и проверьте readiness, SSE, создание заявки и доставку уведомления.
5. При несовместимой миграции откатывайте БД из согласованного backup. Не выполняйте downgrade на работающей production БД без отдельного плана восстановления.

В supplied Compose версии сервисов закреплены тегами; при формировании релиза рекомендуется разрешить теги в image digests и хранить эти digests вместе с релизом. Обновляйте патчи безопасности после тестов.

## Ограничения и решения

- Compose предназначен для одного хоста. Для HA нужны managed PostgreSQL, Redis, приватное общее хранилище и иной способ распределения bot updates.
- Nginx завершает HTTPS. Если перед ним ещё один proxy, отдельно настройте доверенную цепочку IP, иначе rate limiting будет видеть IP этого proxy.
- Карта использует OpenStreetMap tiles. Для значительного трафика настройте собственный или договорной tile provider и соблюдайте его usage policy; исходящие tile-запросы раскрывают провайдеру область карты.
- Приватные фото никогда не раздаются через публичный alias Nginx. В `.env` нет публичного bucket URL.
- Лимит файла — максимум 10 МБ; изображения декодируются, проверяются на decompression bomb, EXIF удаляется, результат сохраняется JPEG до 4096 px. PNG/WebP принимаются API, но бот принимает только Telegram `photo`, не `document`.
- CSV/Excel ограничены 50 000 строками на один экспорт; сузьте период для больших объёмов.
- Аудит и история не имеют delete endpoints. Защитите права администратора БД; application-level журнал сам по себе не является внешним tamper-proof хранилищем.
- Функция проверки счёта — точка подключения реестра абонентов. При интеграции добавьте отдельные статусы «не найден», «API недоступен»; не выдавайте проверку формата за существование счёта.
